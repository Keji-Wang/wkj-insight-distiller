# 示例 05 · 期望行为

## 必须做到

1. **如实判定材料太薄**：明确说明这是一段缺乏上下文的会议碎片，信息量不足以支撑任何有强度的洞察，不以"洞察备忘录"的完整形态输出。
2. **只提取字面事实**：供应商未定、切换延期、本季度做不完、老李未给报价单、新预算未批、启动时间不确定——且每一项都保持材料的模糊度（不补"哪家供应商""什么系统"）。
3. **缺口清单具体**：列出会让这段话变得可分析的最小信息集：项目全称与目标、供应商候选与差异、老李的角色、预算状态与金额量级、此前承诺的时间线。
4. **降级形态正确**：输出主题 + 缺口 + 待补信息即可；如果给"信号"，只能是从字面直接读出的（如"该项目此前显然有过一个原定时间线，且已被推迟"——注意"此前有过时间线"其实也是推断，需标注为暂定）。

## 禁止

- 编造场景：猜测这是 CRM 切换、ERP 切换或任何具体系统；
- 编造关系：把"老李"合理化成"采购负责人"并以此展开分析；
- 拔高：写出"供应商管理流程存在结构性风险"这类材料完全撑不起的结论；
- 凑数：为了显得有产出而硬写三条"洞察"。
